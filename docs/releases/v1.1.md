# kalo v1.1

一个用 C++17 写的终端文本编辑器，单二进制、零依赖。本版本集中重写了语法高亮引擎，
支持语言从 2 门扩到 8 门，并修掉了三类跨行着色错误。

---

## 语法高亮引擎重构

这一版的重点不是"多支持几种语言"，而是把规则表达能力重做了一遍。
原来的实现有两个结构性限制：注释规则是**单值**字段，跨行状态是**布尔量**。
这两点导致任何"成对起止符"的语法都表达不准。

### 1. 块规则：块注释与跨行字符串统一抽象

新增 `BlockRule`（`start` / `end` / 颜色）。理由是块注释与跨行字符串在词法上完全同构——
都是「起始符 → 内容染色 → 结束符」。统一之后，Python 三引号、Go 原始字符串、
JavaScript 模板串都只是多一条**数据**，不需要改状态机。

```cpp
r.blocks = {{"/*", "*/", Hl::MlComment}, {"`", "`", Hl::String}};
```

### 2. 多套规则 + 最长匹配优先

行注释与块规则的字段从单值改为列表，多套同时命中时取最长的一条：

| 语言 | 规则 | 匹配结果 |
| :-- | :-- | :-- |
| Rust | `//` 与 `///` | `///` 胜出（更具体） |
| Python | `"` 与 `"""` | `"""` 胜出 |
| C/C++、Java | `/*` 与 `/**` | `/**` 胜出 |

### 3. 跨行状态从布尔量改为状态结构

`SyntaxState` 记录的是**「当前处于第几条块规则」**（`Row::hlState`）。
原来只有"是否在块注释里"这一个比特，无法表达"在三引号里"。
文件切换导致规则表变化时，状态里那个下标会失效，`highlightRow` 开头有越界夹取保护。

### 4. 关键字查找改为哈希表

关键字表从 `vector` + `std::find` 改为 `unordered_set`。语言变多之后，
逐行逐标识符的线性查找是明确的瓶颈。SQL 走大小写不敏感路径，
在规则表初始化时把关键字表统一折叠为小写，查询前也转小写。

## 新增能力

### 支持语言：2 门 → 8 门

| 语言 | 后缀 |
| :-- | :-- |
| C / C++ | `.c` `.h` `.cc` `.cpp` `.cxx` `.hh` `.hpp` `.hxx` |
| Java | `.java` |
| JavaScript | `.js` `.jsx` `.mjs` `.cjs` |
| TypeScript | `.ts` `.tsx` `.mts` `.cts` |
| Go | `.go` |
| Rust | `.rs` |
| Python | `.py` `.pyw` `.pyi` |
| SQL | `.sql` |

认不出的后缀不着色（沿用原有行为，不是出错）。

### 修好的跨行着色

以下三种语法在 1.0 里**一行结束时状态就丢了**，导致下一行开始错误着色：

- Python 的 `"""` / `'''` 多行字符串
- Go 的反引号原始字符串
- JavaScript 的模板字符串

### 新增着色类型

除原有的关键字、类型名、字符串、数字、注释外，新增：

- **函数调用** —— 标识符后紧跟 `(`（亮蓝）
- **常量与内置值** —— `true` / `NULL` / `nil` / `print` 等（亮青）
- **类型** —— Go / Rust / Python 的首字母大写约定（亮蓝）

### 数字识别增强

支持 `0x` / `0X` 十六进制、`0b` / `0B` 二进制、`0o` / `0O` 八进制前缀，
以及小数、科学计数法（`1.5e-3`）与下划线分隔（`1_000_000`）。
同时保持"标识符后紧跟的数字不算数字"，所以 `my123` 不会被拆开。

## 升级提示

若你 fork 过本项目并调用了高亮接口，`Syntax::highlightRow` 的签名变了：

```cpp
// 1.0
void highlightRow(Row &row, const SyntaxRule *rule, bool prevOpenComment, bool &outOpenComment);
// 1.1
void highlightRow(Row &row, const SyntaxRule *rule, const SyntaxState &prev, SyntaxState &out);
```

`SyntaxState` 有 `SyntaxState(bool)` 构造可以从旧的布尔值过渡。
`Row::hlOpenComment` 相应改为 `Row::hlState`。

## 已知限制

- JavaScript 的正则字面量（`/re/`）暂不识别，可能与除号混淆。
- C/C++ 的预处理指令（`#include`）没有单独着色。
- Rust 的生命周期标注（`'a`）与字符字面量（`'x'`）会混淆。
- 画面上不做行号，不做软换行。
- 垂直方向不处理 Unicode 组合字符与从右到左文字。
